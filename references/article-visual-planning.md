# 新闻文章配图策划

用于用户提供整篇文章、要求多张配图、或询问插图放在哪里的任务。单张图片请求继续按 `SKILL.md` 处理。

## 先判断是否值得配图

通读文章，抓住中心事件、叙事进展和信息重点，再判断哪些内容需要视觉补充。图片可以交代现场、呈现关键行动、补足人物处境，或帮助读者看懂空间与关系。不要逐段配图、按固定间隔插图，也不要为凑数量重复画同一场景。若图片不会让信息更清楚，就说明原因并建议不配。

## 选图与组织顺序

- 按文章复杂度建议必要的图片数量；普通文章通常先考虑 1–3 张，长篇或多阶段事件可增加。
- 每张图只承担一个主要作用：交代环境、呈现行动、补充人物处境、解释物件或关系、承接叙事转折。
- 只有不同景别能补充新信息时才组合环境全景、人物中景和细节近景；避免把同一瞬间拆成重复配图。
- 多张图保持相同的纪实色彩和自然光倾向。只有文章明确说明是同一人物、地点或连续事件时，才建立视觉连续。
- 若同一已确认人物或地点会反复出现，先从文章提取一条简短的“系列共用线索”，并原样用于相关提示词；只写已知信息，外貌、服装、时间或环境细节未交代时不要补设定。不同时间点只保持必要的一致性，不要把它们拼成文章未确认的连续瞬间。
- 不同画面不共用已确认主体或地点时，只保持整体摄影语言一致，不强行指定同一人物、服装或场景。
- 默认保留原文。用户未要求改写或回填文件时，只给配图计划与提示词。

## 提示词与插入位置

按文章阅读顺序逐张输出：

1. **插入位置**：引用文章中可搜索的标题或简短原句，并说明放在其前或后；不要只写“第二段后”。
2. **配图作用**：说明它给读者补充了什么信息。
3. **系列共用线索（按需）**：多张图确实共享文章确认的人物或地点时，列出将复用的短线索；无共享对象时省略。
4. **画面重点**：只描述文章已确认的主体、动作、环境与关系。抽象观点若无法忠实转为可见新闻场景，不要编造隐喻性事件。
5. **中文提示词**：写一条可直接使用的法新社风格纪实摄影提示词；相关画面沿用系列共用线索。若用户需要跨模型复用，再附英文版。
6. **发布标注**：如果画面描绘真实事件或人物，在图片旁标注“AI 生成示意图”；标注不要放进图像提示词。

提示词不得补入原文没有的地点、时间、人物身份、伤亡、机构、屏幕读数或事件结果。图注和插入说明也只复述已确认的信息。

## 轻量输出格式

先用一两句话概述配图策略和数量，再逐张列出：

```markdown
### 配图 1：{简短名称}
- 插入位置：在“{文章中的短锚点}”之后
- 作用：{补充的信息}
- 提示词：{可复制提示词}
- 发布标注：AI 生成示意图
```

只有用户明确要求生成、插图或改写文章文件时，才继续执行这些操作。图片文件准备好后，可用 `scripts/insert_illustrations.py` 按计划锚点回填：

```bash
python scripts/insert_illustrations.py --article report.md --manifest images.json
```

清单为 JSON 数组，每项包含 `anchor`、`position` 和 `image_path`，可选 `caption`、`alt`、`disclosure`。`alt` 简短描述图中可见内容；`caption` 只写文章确认的事实；AI 说明与图注分开。脚本默认用“AI 生成示意图”，转绘实际照片时应将 `disclosure` 设为“AI 编辑示意图”。

```json
[
  {
    "anchor": "志愿者清晨抵达",
    "position": "after",
    "image_path": "images/food-station.webp",
    "alt": "志愿者整理蔬菜和罐头",
    "caption": "社区中心食物站的志愿者整理捐赠食品。",
    "disclosure": "AI 生成示意图"
  }
]
```

锚点必须唯一匹配标题或段落；缺失或重复时脚本会报错，不会把图片静默追加到文末。默认输出同目录的 `report_afp_illustrated.md`，不会覆盖原文；只有指定 `--force` 才会覆盖已有输出文件。
